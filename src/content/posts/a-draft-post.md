如果你是通过本地开发服务器看到这一页的，那说明草稿机制正在按预期工作。

## 这一篇为什么能被你看到

它的 frontmatter 里写着：

```yaml
draft: true
```

而此刻你多半正运行着 `npm run dev`。规则是这样的：

| 场景 | 草稿文章的表现 |
| --- | --- |
| `npm run dev`（开发模式） | **照常显示**，可以边写边预览排版效果 |
| `npm run build`（生产构建） | **完全跳过**，不会生成任何页面 |
| 首页、归档、分类、标签列表 | 生产构建中不出现；开发模式中出现 |
| RSS / Atom / 站点地图 | 生产构建中不出现 |
| Pagefind 搜索索引 | 生产构建中不出现（索引建立在产物之上） |
| 侧栏目录树 | 生产构建中不出现 |

所以你不用担心「草稿被搜索引擎抓到」这件事：它从来没有进入过线上产物。

:::note
开发模式下草稿会混在列表里，容易让人误以为已经发布。写草稿时建议顺手把 `description` 写成一句话说明「这是草稿」，看到卡片时就能立刻反应过来。
:::

## 什么时候该用草稿

- **写到一半的长文**：先把结构搭好、素材堆进去，发布前再把 `draft` 改成 `false`；
- **需要配图的文章**：图还没做好，但正文想先存进仓库，避免本地文件丢失；
- **不确定要不要发的选题**：先写，放着，过几周再回头看；
- **临时存档**：准备大改但暂时没时间，先用草稿状态保住当前版本。

## 发布它

把这一行改掉，它就变成一篇正式文章：

```yaml
draft: false
```

顺手再检查三件事：`published` 的日期是不是想发布的那天、`description` 是否写得够清楚、`tags` 与 `category` 是否已经归好类。然后重新构建、部署，文章就会出现在列表最前面。

想彻底删掉它，直接从 `src/content/posts/` 里移除文件即可——内容即文件，没有别的清理动作。

:::tip
如果只是想「暂不发布」，又不想每次部署都惦记着它，用草稿比用注释更安全：注释掉的 frontmatter 会导致字段缺失，而草稿是一个受支持的正式状态。
:::
