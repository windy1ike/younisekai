一直想有个地方放自己的文字：零零碎碎的念头、看完书之后的笔记、折腾东西时踩过的坑。
社交平台太吵，笔记软件又太安静——没人看，也就懒得写完整。所以就有了这里。

## 文章就是文件

这个博客没有后台，没有数据库，也不用登录。**每一篇文章就是 `src/content/posts/` 目录下的一个 `.md` 文件。**

想写的时候新建一个文件，写完保存，页面上就有了。想改就直接改，想删就直接删。所有历史都在 git 里，写坏了随时能回退。

新建文章最快的方式是命令行：

```bash
npm run new -- "文章标题" --tags 随笔,读书
```

它会生成一个带好 frontmatter 的 Markdown 文件，直接打开就能写。

## 文件开头那段是干什么的

每个 `.md` 文件最上面那两块 `---` 之间的部分叫 frontmatter，用来告诉博客这篇文章叫什么、什么时候发的、属于什么标签：

```yaml
---
title: '开始写点东西'      # 标题
description: '一句话摘要'   # 列表页显示，不写就自动截取正文
pubDate: 2026-09-28       # 发布日期
tags: ['随笔', '博客']     # 标签，可以有多个
draft: false              # true = 草稿，本地能看，发布时不带上
---
```

写错了字段名不用担心，构建的时候会直接报错，并且告诉你是哪个文件的问题。

## 草稿机制

写到一半不想让人看到，就把 `draft` 写成 `true`。

草稿在本地预览时会照常出现（带一个「草稿」标记），但正式构建发布时会自动排除，也不会进 RSS。

## 关于标签

标签写在 frontmatter 的 `tags` 里，会自动出现在[标签页](/tags/)和文章顶部。
同一篇文章的多个标签之间用逗号分隔即可。

## 接下来

想把这堆东西放到公网上，随便挑一个：

- **GitHub Pages**：免费，推上去就自动构建（仓库里已经放好了 `.github/workflows/deploy.yml`）
- **Vercel / Netlify**：连上仓库，零配置，自带域名和 HTTPS
- **自己的服务器**：`npm run build` 之后把 `dist/` 目录扔给 nginx 就行

部署前记得把 `astro.config.mjs` 里的 `site` 改成自己的域名——RSS 和站点地图要用它生成绝对链接。

就这些。去写下一篇吧。
